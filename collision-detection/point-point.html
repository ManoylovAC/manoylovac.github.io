Точка і Точка

Почнімо з найпростішого випадку — перевірки зіткнення двох точок. У геометрії та комп’ютерній графіці точка не має ані ширини, ані висоти: вона описується лише однією парою координат x та y. Тож дві точки стикаються тоді й лише тоді, коли вони опиняються в тому самому місці полотна — тобто коли їхні координати x та y повністю збігаються! 

if (x1 === x2 && y1 === y2) {
  // координати збіглися: зіткнення!
} else {
  // точки в різних місцях: зіткнення немає
}

Зверніть увагу на оператор логічного «І» (&&): зіткнення зараховується лише тоді, коли обидві рівності істинні одночасно. Якби збіглася лише координата x, це означало б, що точки просто лежать на одній вертикалі одна над одною.

Щоб не писати цю перевірку щоразу вручну, загорнімо її в окрему функцію collidePointPoint(). Як аргументи передамо координати x/y першої точки (x1, y1) та другої точки (x2, y2). Функція повертатиме логічне значення true або false: 

function collidePointPoint(x1, y1, x2, y2) {
  if (x1 === x2 && y1 === y2) {
    return true;
  }

  return false;
}

Помітили невелике спрощення? Ми не писали блок else { return false; }. Річ у тім, що інструкція return миттєво завершує роботу функції. Якщо умова в if виконається, функція одразу поверне true і далі не піде. А якщо умова не виконається, виконання дійде до останнього рядка і поверне типову відповідь false («зіткнення немає»). Такий запис чистіший, і ми користуватимемося ним упродовж усієї книги.

До речі, досвідчені розробники часто скорочують подібні функції до одного рядка, адже сам вираз порівняння вже дає true або false: 

function collidePointPoint(x1, y1, x2, y2) {
  return x1 === x2 && y1 === y2;
}

Обидва варіанти працюють однаково. У наших прикладах ми здебільшого залишатимемо розгорнутий запис із if, щоб кожен крок алгоритму легко читався з першого погляду.

Маючи під рукою першу функцію виявлення зіткнень, випробуймо її в дії! Пограйтеся з інтерактивним прикладом угорі сторінки: наведіть темну точку курсора на блакитну точку в центрі й подивіться, як полотно спалахне помаранчевим кольором.

Ви напевно помітите, що «влучити» однією точкою в іншу непросто! Хоча ми намалювали точки жирними кружечками за допомогою strokeWeight(15), щоб їх було добре видно очам, математично кожна точка залишається одним-єдиним пікселем. Як зробити зіткнення точок поблажливішим за допомогою «буферної зони», ви зможете спробувати в першій секції завдань.

Нижче наведено повний код скетчу. Спробуйте скопіювати його в онлайн-редактор p5.js, запустити й поекспериментувати зі значеннями: 

// координати нерухомої цільової точки
let targetX;
let targetY;

function setup() {
  createCanvas(window.innerWidth, window.innerHeight);
  noCursor();
  strokeWeight(15); // збільшуємо візуальний розмір точок для наочності

  // округлюємо до цілих пікселів на випадок непарної ширини/висоти вікна
  targetX = round(width / 2);   // горизонтальний центр полотна
  targetY = round(height / 2); // вертикальний центр полотна
}

function draw() {
  const px = round(mouseX);
  const py = round(mouseY);

  // перевіряємо, чи збігаються координати курсора з цільовою точкою
  const isColliding = collidePointPoint(px, py, targetX, targetY);

  // змінюємо колір фону залежно від результату перевірки
  if (isColliding) {
    background(255, 150, 0); // помаранчевий фон під час зіткнення
  } else {
    background(255);         // білий фон, коли точки не збігаються
  }

  // малюємо статичну цільову точку
  stroke(0, 150, 255);
  point(targetX, targetY);

  // малюємо рухому точку на місці курсора
  stroke(0, 150);
  point(px, py);
}

// перевірка на зіткнення двох точок
function collidePointPoint(x1, y1, x2, y2) {
  // чи обидві точки мають однакові координати?
  if (x1 === x2 && y1 === y2) {
    return true;
  }

  return false;
}
